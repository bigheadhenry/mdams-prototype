# 标准演示主链路

- 最后核对日期：2026-05-21
- 文档状态：current
- 核对口径：用于馆内汇报、开发自测和回归验证的标准路径；以当前已实现的稳定主链路为准
- 自动化护栏：`backend/tests/test_standard_demo_flow.py`

## 1. 目标

本文件定义 MDAMS Prototype 的标准演示主链路。它的目标不是展示所有功能，而是用一条可重复、可验证的路径证明当前系统已经形成从资源入库、平台聚合到申请交付的最小业务闭环。

建议每次重要演示、部署前验收或主链路改动后，都按本文进行人工走查，并配合运行对应自动化测试。

## 2. 演示前准备

### 2.1 服务状态

确认以下服务已经启动并可访问：

- 前端：`http://localhost:3000`
- 后端 API：`http://localhost:8000/docs`
- 健康检查：`http://localhost:8000/health`
- 就绪检查：`http://localhost:8000/ready`
- Cantaloupe / IIIF 图像服务：通过前端代理或后端配置可访问

### 2.2 推荐账号

标准演示可使用以下账号分段完成：

| 阶段 | 推荐账号 | 用途 |
| :--- | :--- | :--- |
| 平台管理与上传 | `system_admin` | 查看全部菜单、上传资源、管理申请 |
| 普通资源申请 | `resource_user` | 浏览统一资源目录、加入申请车、提交申请 |
| 申请审批与导出 | `system_admin` 或具备审批权限的账号 | 审批申请、导出交付包 |

默认测试密码为 `mdams123`。

## 3. 标准演示路径

### 3.1 登录与总览

1. 打开前端首页。
2. 使用 `system_admin` 登录。
3. 确认进入总览页。
4. 确认页面显示当前用户、角色、可见菜单和资源统计。

验收点：

- 登录成功后能够看到总览、二维资源、入库处理、统一资源目录、三维管理、申请管理、影像信息录入等入口。
- 菜单可见性与当前角色一致。

### 3.2 二维资源上传与详情

1. 进入“入库处理”或“二维资源”相关入口。
2. 上传一张普通图片文件。
3. 返回二维资源列表。
4. 打开该资源详情。

验收点：

- 资源状态为 `ready`。
- 列表可显示缩略图或预览入口。
- 详情页展示文件、状态、元数据层、生命周期、下载和 BagIt 输出动作。

### 3.3 IIIF 与 Mirador 预览

1. 在二维资源列表或详情页点击预览。
2. 打开 Mirador 预览器。
3. 确认 Manifest URL 指向 `/api/iiif/{asset_id}/manifest`。
4. 确认图像可加载。

验收点：

- Manifest 可返回。
- IIIF service URL 可被 Mirador 使用。
- 对未就绪或无权限资源，应给出明确失败状态，而不是静默空白。

### 3.4 统一资源目录与统一详情

1. 进入“统一资源目录”。
2. 搜索刚才上传的资源名称。
3. 打开统一资源详情。
4. 从统一详情查看来源记录、资源动作和预览入口。

验收点：

- 资源出现在 `image_2d` 来源下。
- `source_system/source_id` 可唯一定位该资源。
- 统一详情能够读取来源详情，并保留平台动作：预览、来源详情、下载、BagIt 导出、加入申请车。

### 3.5 申请车与申请提交

1. 切换或继续使用具备 `application.create` 权限的账号。
2. 在统一资源目录或统一详情中点击“加入申请车”。
3. 打开“申请车”。
4. 填写申请人、单位、用途、使用范围。
5. 提交申请。

验收点：

- 申请条目保留 `source_system`、`source_id`、资源标题、来源标签和交付格式。
- 提交后申请状态为 `submitted`。

### 3.6 审批与交付包导出

1. 使用具备审批权限的账号进入“申请管理”。
2. 找到刚才提交的申请。
3. 审批通过。
4. 导出交付包。

验收点：

- 审批后状态为 `approved`。
- 导出后状态进入 `fulfilled`。
- 交付包中包含申请说明和可交付文件；二维本地资产应包含实际文件。

### 3.7 三维与视频来源抽查

1. 回到统一资源目录。
2. 切换三维或视频来源标签。
3. 打开一个三维或视频资源详情。

验收点：

- 三维资源进入统一详情中的三维预览或来源详情。
- 视频资源进入统一详情中的在线播放或下载入口。
- 二维、三维、视频均遵守统一平台的来源定位和动作结构。

## 4. 自动化回归

标准主链路的最小自动化护栏为：

```powershell
python -m pytest backend\tests\test_standard_demo_flow.py -q
```

该测试覆盖：

- 二维图片上传
- 资产详情读取
- IIIF Manifest 生成
- 统一资源目录查询
- 统一资源详情读取
- 申请创建
- 审批通过
- 交付包导出

完整后端回归可运行：

```powershell
python -m pytest backend\tests -q
```

前端关键入口回归可运行：

```powershell
cd frontend
npm run test -- dashboard.spec.ts
```

## 5. 演示失败时优先排查

| 现象 | 优先检查 |
| :--- | :--- |
| 登录失败 | `AUTH_DEFAULT_PASSWORD`、测试用户 seed、`/api/auth/users` |
| 图片上传失败 | `UPLOAD_DIR`、挂载目录权限、后端日志 |
| Mirador 空白 | Manifest 是否可访问、Cantaloupe URL、IIIF proxy 配置 |
| 统一目录找不到资源 | 来源适配器、资源状态、筛选条件、`/api/platform/resources` |
| 申请无法提交 | 当前角色是否有 `application.create`，申请车条目是否有 `asset_id` 或 `source_system/source_id` |
| 导出失败 | 申请是否 approved，二维资产物理文件是否存在 |

## 6. 当前边界

- 标准演示主链路优先覆盖二维资源到申请交付的完整闭环。
- 三维和视频在本流程中作为统一平台多模态来源抽查，不等同于完整生产链路验收。
- AI / Mirador 辅助能力不纳入本标准主链路的必过项，可作为扩展示范。
- 更复杂的审批流、生产级身份治理、长期保存和迁移能力，应在主链路稳定后继续推进。

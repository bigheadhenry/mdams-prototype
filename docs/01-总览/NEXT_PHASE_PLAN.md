# MDAMS Prototype 下一阶段计划

> 最后更新：2026-07-06
> 当前执行计划：`.hermes/plans/2026-07-05_mdams-next-phase-deepseek-v4-flash.md`

## 1. 目标

这份文档描述 MDAMS Prototype 当前阶段最值得优先推进的方向。

当前系统已经不只是一个二维影像 PoC，而是已经具备：

- 二维影像资源管理与 IIIF 预览
- 三维资源管理与 Web 查看
- 统一平台目录与统一详情
- 登录、角色、权限与范围控制
- 利用申请与交付闭环

因此，下一阶段的目标不再是"证明技术可行"，而是：

> **把当前可用能力整理成稳定、可维护、可逐步扩展的馆内数字资源底座。**

## 2. 当前阶段判断

### 2.1 已经完成的部分

当前项目已完成的重点包括：

- 二维影像主链路可用
- 三维子系统可用
- 统一平台入口可用
- 登录和权限框架可用
- 申请与交付流程可用
- 工作日志和测试分层已建立

### 2.2 仍然需要继续补的部分

当前最需要继续补的不是"更多零散功能"，而是：

- 更稳的统一平台层
- 更清晰的资源范围与权限规则
- 更完整的治理和长期保存能力
- 更实用的测试和回归体系

### 2.3 当前阶段的准确定位

> **高价值技术原型已经成型，正在向稳定可持续开发底座过渡。**

## 3. 下一阶段优先级（2026-07）

当前执行阶段按 M0–M6 结构推进，详见计划书 `.hermes/plans/2026-07-05_mdams-next-phase-deepseek-v4-flash.md` 和可视化路线图 `memory/MDAMS下一阶段完善路线图_DeepSeek执行版.html`。

优先级结构如下：

| 优先级 | 内容 | 对应阶段 |
|--------|------|----------|
| P0 | 文档入口与事实收敛 | M0–M1 |
| P1 | 统一平台契约和检索边界 | M2–M3 |
| P2 | 申请交付、权限治理、长期保存输出契约 | M4–M5 |
| P3 | UI 原型融合和演示体验 | M6 |

### P0：文档入口与事实收敛

目标：
> 消除多套事实，确保后续所有开发以当前代码为基准。

- M0 执行前基线确认（只读核对）
- M1 对齐 NEXT_PHASE_PLAN、清理冲突描述

### P1：统一平台契约和检索边界

目标：
> 为统一平台来源建立测试级契约，明确搜索与筛选边界。

- M2 平台最小字段契约 + 契约测试 + 统一详情 fallback
- M3 搜索入口边界文档 + 搜索契约测试

### P2：申请交付、权限治理、长期保存输出契约

目标：
> 让申请、审批、导出、权限链路更可解释、可测试、可演示。

- M4 申请状态机审查 + 审批权限与 owner scope 回归测试
- M5 选择一条主链路做 preservation contract + 事件边界测试

### P3：UI 原型融合和演示体验

目标：
> 将 HTML 设计原型中的设计 token 和有效交互沉淀到真实前端。

- M6 提取设计 token + 改造三个高频页面

### 非目标（不做 / 不优先做）

- 不新增新资源类型（不做完整 DAMS）
- 不做复杂工作流引擎
- 不新增大规模重构
